# EcoSchool / EcoBiz Copilot

Рабочий MVP для трека **EcoFin** Future Minds Hackathon 2026. Сервис анализирует ежедневное потребление электроэнергии школы или малого бизнеса, ищет расход в нерабочие дни, считает потенциальную экономию и выдаёт понятную рекомендацию.

## Что умеет MVP

- принимает CSV/XLSX с `date` и `consumption_kwh`;
- сам создаёт `is_workday` по выходным, праздникам РК и школьным каникулам, если этой колонки нет;
- сохраняет вручную заданную `is_workday`, если школа передала точный график;
- находит аномалии через нижний квартиль расхода нерабочих дней;
- показывает избыток кВт·ч, потенциальную экономию в тенге и CO₂;
- вызывает Gemini для человеческой рекомендации, но всегда работает без ключа и интернета благодаря локальному fallback;
- отдаёт результат через независимый FastAPI-контракт.

## Структура

```text

```

## Быстрый старт

Нужен Python 3.10+.

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python data/generate_sample.py
uvicorn api:app --reload
```

После запуска откройте `http://127.0.0.1:8000/docs`. Это готовый интерфейс FastAPI, где можно загрузить `data/sample_data.csv` и показать живой сценарий без фронтенда.

Проверка здоровья API:

```bash
curl http://127.0.0.1:8000/health
```

## Запрос к API

`POST /analyze` принимает `multipart/form-data`:

- `file` — CSV, XLSX или XLS;
- `tariff` — необязательный тариф в ₸/кВт·ч;
- `co2_kg_per_kwh` — необязательный коэффициент CO₂ в кг/кВт·ч;
- `extra_off_periods` — необязательный JSON-массив дополнительных периодов простоя, например `[ ["2026-12-15", "2026-12-21"] ]`.

Пример для PowerShell:

```powershell
curl.exe -X POST "http://127.0.0.1:8000/analyze" `
  -F "file=@data/sample_data.csv" `
  -F "tariff=28.12"
```

Основной контракт ответа:

```json
{
  "impact": {
    "total_excess_kwh": 0.0,
    "savings_kzt": 0.0,
    "co2_saved_kg": 0.0,
    "anomaly_days": 0,
    "tariff_kzt_per_kwh": 28.12,
    "co2_kg_per_kwh": 0.85
  },
  "anomaly_dates": ["2025-12-15"],
  "recommendation": "…",
  "recommendation_source": "gemini",
  "baseline_reliable": true,
  "baseline_kwh": 0.0,
  "off_day_samples": 0,
  "tariff_note": "…"
}
```

`baseline_reliable: false` означает, что в истории меньше пяти нерабочих дней. В этом случае результат нельзя подавать как надёжный вывод: загрузите более длинную историю или уточните график школы.

`recommendation_source` показывает, откуда получен текст: `gemini` — успешный ответ Gemini API; `fallback` — локальный шаблон, использованный при отсутствии ключа, проблеме с сетью, неверной модели или ошибке API. Сервер записывает в консоль начало/успех вызова Gemini или полный текст ошибки, но никогда не выводит сам API-ключ.

## Формат данных

Минимальный реальный файл:

```csv
date,consumption_kwh
2026-03-19,420.5
2026-03-20,410.2
```

Допустимый расширенный файл с точным графиком школы:

```csv
date,consumption_kwh,is_workday
2026-03-19,420.5,0
2026-03-20,410.2,0
```

`is_workday=1` — обычный рабочий день, `0` — нерабочий. Если есть дубликат даты, сервис оставляет последнюю запись и пишет предупреждение в лог. Пустой, текстовый или отрицательный расход удаляется с предупреждением; это сделано, чтобы «грязная» выгрузка не тихо искажала расчёт.

## Как работает детекция

1. Берём только нерабочие дни.
2. Строим базовый уровень: 25-й перцентиль их расхода. Он устойчивее среднего к уже существующим потерям.
3. День — аномалия, если расход выше `база × 1,5`.
4. Избыточный расход в такой день: `факт − база`.
5. Экономия: `избыток × тариф`; CO₂: `избыток × коэффициент CO₂`.

Это статистический anomaly detection, а не нейросеть. Gemini решает другую, объяснимую задачу: переводит проверенные цифры в короткое действие для завхоза. Все числа и даты в рекомендации создаются кодом из результата анализа, а не доверяются модели.

## Gemini и автономный режим

1. Скопируйте `.env.example` в `.env`.
2. Заполните `LLM_API_KEY` ключом Gemini API.
3. Никогда не коммитьте `.env`.

Если ключа нет, интернет недоступен, превышен лимит или Gemini вернул ошибку, `advisor.py` автоматически возвращает полноценную локальную рекомендацию. Поэтому демонстрация не зависит от Wi‑Fi.

Ключ читается из `.env`, лежащего рядом с `advisor.py`, ещё при импорте модуля и до обращения к переменным окружения. После изменения `.env` перезапустите `uvicorn`; в логе появится строка `LLM configuration` с путём `.env` и источником ключа, но без самого секрета.

По умолчанию используется `gemini-3.5-flash-lite`. Если в логе есть `404 NOT_FOUND` с сообщением о модели, обновите `GEMINI_MODEL` в `.env` на модель, которую прямо рекомендует сообщение Gemini.

## Тарифы — важное ограничение

По умолчанию используется **28,12 ₸/кВт·ч** — среднеотпускной тариф АО «Астана-РЭК» для физических лиц с НДС, действующий с 01.07.2026. Это **демонстрационное** значение, а не тариф школы. Для финального демо нужно подтвердить тариф бюджетной организации по договору или на `astanaenergosbyt.kz` и передать его в поле `tariff`.

В `config.py` есть источники и контекст трёх астанинских тарифных значений; ни одно не подставляется как «официальный школьный тариф».

Коэффициент CO₂ по умолчанию **0,85 кг CO₂/кВт·ч** также является только демонстрационным допущением исходного MVP. Не называйте итоговые килограммы «официально подтверждённым сокращением», пока команда не выберет методологию и не подтвердит актуальный коэффициент для периода анализа. После этого передайте подтверждённое значение в `co2_kg_per_kwh`.

## Q&A: что должна объяснить команда

### Участник 1 — данные и статистическое ядро

- **Почему 25-й перцентиль, а не среднее?** Среднее может вырасти из-за уже аномальных дней. 25-й перцентиль ближе к корректному дежурному режиму здания.
- **Почему порог 1,5?** Это понятный MVP-порог: расход должен быть заметно выше базы. Его можно вынести в настройку после получения реальной истории школы.
- **Почему `baseline_reliable` может быть false?** По 1–4 нерабочим дням нельзя честно судить о норме. Код всё равно показывает предварительный сигнал, но не скрывает слабость данных.
- **Что происходит с грязными данными?** Невалидные строки удаляются с предупреждением, дубль даты заменяется последней записью, данные сортируются.

### Участник 2 — Gemini и API

- **Зачем LLM, если формулу можно посчитать без неё?** Формула находит проблему, а LLM переводит её в действие для нетехнического пользователя. Это отдельная функция, а не «чат ради чата».
- **Как вы не даёте Gemini придумать цифры?** Числа и даты добавляет Python из `impact` и `anomaly_dates`. Gemini получает факты для контекста, но его текст очищается от цифр; при ошибке есть шаблон из тех же данных.
- **Что будет без сети?** API не упадёт: `generate_recommendation` вернёт автономную рекомендацию.
- **Почему CORS открыт?** Это только для локальной разработки, чтобы будущий фронтенд работал на другом порту. При публичном деплое origin будет ограничен доменом приложения.
